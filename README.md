# pair-wise-yy-59 法律文件披露、去密与发布质控工作台

用于诉讼披露批次中的区域去密、原页/发布页双人复核、文档标签和发布门禁。PDF.js 真实渲染示例文档，去密区域可绘制、确认并持久化到本地草稿。

## 发布基线（去密区域 × 发布批次 × 质检结论）

三份数据在 `src/baseline/` 中接成同一条基线：

- **修订与指纹**：每份文档有 `revision` 与去密区域集合的内容指纹（`contentHash`）。区域新增/改动即推进修订并写入修订历史；确认（draft→confirmed）不产生新修订。
- **确认留依据**：确认去密区域时写入当时的修订号、指纹、操作者与时间。两人同时提交同一区域时走 CAS：先到者生效，后到者收到 `already-confirmed` 并看到先到者，后写不覆盖。
- **内容一变即失效**：区域内容变化后，所有挂接该文档的**未发布批次**的有效质检结论置为 `invalidated`，文档回到"待复核"，结论上记录受影响批次；必须按新修订重新确认才能再出清单。
- **已发出清单冻结**：清单是不可变快照（修订号、指纹、结论 ID、复核人），冻结后不再重写；基线页逐条对照当前内容，标出"已漂移至 rN"，新内容只能走新批次。
- **发布门禁**：批次内每份文档都要有锚定当前修订+指纹的通过结论，否则 `evaluateBatch` 返回阻断原因，`buildManifest` 拒绝出清单。
- **追加式登记册**：清单项只追加；写入失败保留本地草稿（含尝试次数与错误），可重试，重试沿用原批次号；同一批次号在登记册中只追加一次（幂等）。
- **旧草稿迁移**：v1 持久化数据没有修订号，v2 迁移与 rehydrate 时按当前内容补齐（文档从 r1 起、指纹按区域集合计算、已确认区域补上依据修订）。

关键入口：

- 领域纯函数：`src/baseline/domain.ts`
- 写入端（可注入失败）：`src/baseline/repository.ts`
- 种子局面（含失效结论与冻结漂移）：`src/baseline/seed.ts`
- Zustand 接线/迁移/草稿：`src/store.ts`

## 技术栈

React、Radix UI 风格组件、Zustand、TanStack Router、TanStack Query、PDF.js、Vite、TypeScript、Vitest。

## 运行

```bash
npm install
npm run dev
```

访问 `http://localhost:62059`。示例 PDF 由浏览器端生成后交给 PDF.js 渲染，不需要外部文件。

```bash
npm run build
npm test        # 23 个领域 + store 集成测试
```

## 演示路径

1. **文档集**：DOC-00418 显示"结论失效 · 待复核"（r1 结论已被 r2 内容作废）；DOC-00435 在 r2。
2. **去密审阅 DOC-00418**：确认草稿区域 R-02（依据记为 r2）；属性面板可用"模拟另一操作者同时确认"演示先到先得。绘制新区域会立即推进修订并弹出去失效提示。
3. **发布质检**：切到 DOC-00418，勾选校验项与元数据清理后通过，结论锚定 r2。
4. **发布基线**：
   - BATCH-01 门禁通过后生成清单；勾选"模拟下一次清单写入失败"可验证失败保留草稿、重试追加、批次号不重复。
   - BATCH-02 已冻结在 r1，而文档已到 r2：清单条目标红显示漂移且不可改写。
   - BATCH-03 含同一文档（一份文档挂多个批次），出清单后再改区域，冻结清单保持不变。
